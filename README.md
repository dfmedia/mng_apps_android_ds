Android-only atoms, patterns and token exceptions for MNG's 77 Android market apps. Builds on the [MNG Apps Core Design System](https://github.com/dfmedia/mng_apps_core_ds).

## Tokens (generated, DEC-04)

`tokens/MngBrandColors.kt and tokens/flavors/<flavor>/res/values/mng_brand_colors.xml` is generated by Style Dictionary from the Core repo's `tokens/` (DTCG). **Never edit it here**: change the Core data, then run `npm run tokens && npm run build` in `mng_apps_core_ds`. Usage: `MngBrandPalettes.TDP.navbar` (Compose) or `@color/mng_brand_navbar` from the flavor XML; `MngBrandPalettes.forMarket("tdp")`. Status bar for the running Android version (DEC-15): `palette.statusbarFor(Build.VERSION.SDK_INT)` and `palette.statusbarDarkIconsFor(Build.VERSION.SDK_INT)`; in XML `@color/mng_brand_statusbar` and `@bool/mng_brand_statusbar_dark_icons` (Android 15+ values in `res/values-v35/` for the 7 markets with a status-bar override: navbar, with dark icons only where the bar is exactly #FFFFFF). Every color is written from its exact hex bytes; hex and RGB for each market are in Core `docs/BRAND-COLORS.md`.

## Compile check

Every push runs `.github/workflows/compile.yml` (GitHub Actions, Linux): `build.gradle.kts` is a minimal Android library used **only** for this check. It compiles the Kotlin in `tokens/` and `components/` and links the resources of every flavor (`tokens/flavors/<flavor>/res`, one product flavor each), so a broken XML file or a `@color/…` that points nowhere fails the build. A failure in a generated file means the generator in `mng_apps_core_ds` needs the fix; hand-written component code is fixed here. Results: the repo's **Actions** tab.
